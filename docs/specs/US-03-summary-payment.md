# US-03 — Summary and payment

Status: Approved (HC-1 — candidate as Product Owner proxy, 2026-11-22)
Story: [docs/user-stories/US-03.md](../user-stories/US-03.md) · ADRs: [ADR-0004](../adr/0004-security-public-read-only.md), [ADR-0005](../adr/0005-client-state-and-persistence.md), [ADR-0008](../adr/0008-simulated-payment-gateway.md)

## 1. Goal
Let the person verify everything, accept the country's terms and pay (simulated) exactly once,
receiving a quote number.

## 2. Scope
**In:** summary (policyholder, vehicle, plan, final price), masked document, edit links, terms
from Strapi, accept checkbox, mock payment (success/failure), confirmation screen.
**Out:** real gateway, card capture (forbidden by the brief), emails, PDF policy.

## 4. Business rules (formalised)
- **Masking:** keep the last 3 alphanumeric characters, replace earlier alphanumerics with `•`,
  keep punctuation. Values ≤ 3 chars are fully masked.
- **Pay enabled** ⇔ `termsAccepted ∧ terms ≠ null ∧ status ∉ {processing, paid}`.
- **Payment state machine:** `idle → processing → (paid | failed)`, `failed → processing` (retry).
- **Quote number:** `<COUNTRY>-<YYYYMMDD>-<6 chars [A-Z0-9]>` generated by the mock gateway.

## 5. Gap analysis
| Gap | Question | Decision | Risk |
|---|---|---|---|
| G-01 | "Partially masked" — how much? | Last 3 visible (ASSUMPTION; common practice; constant in `masking.ts`) | Compliance may require last 4 → one constant |
| G-02 | How to present raw values? | Option labels, localized dates, Yes/No | — |
| G-03 | Back button after paying | Guard: `paid` → confirmation | Double charge in a real gateway |
| G-04 | No terms for a country | Block payment | Selling without terms is a legal issue |
| G-05 | Deep link to summary | Guard: plan required | — |
| G-06 | How does QA force a failure? | **NEEDS-ADR → ADR-0008**: visible "Sandbox outcome" selector in the payment card (Approve / Decline) | Mistaken for a real control → labelled "Sandbox" |
| G-07 | Should acceptance survive a language switch? | Yes, same terms version; reset if the version changes | — |

## 6. Data contract — `GET /api/legal-terms?filters[country][code][$eq]=CO&locale=en`
`title` (loc), `body` (long text, loc), `version` (string, non-loc), `country` (relation).

## 7. UX states
Terms loading skeleton / error + Retry · processing spinner inside the button · failure alert
focused · confirmation heading focused · print-friendly confirmation.
